# ardia_core C ABI

`include/ardia_core.h` is generated by cbindgen (`ARDIA_WRITE_HEADER=1 cargo test -p ardia-ffi --test header`) and
carries no comments, so its rules live here. C++ can include it directly: it has its own `extern "C"` guard. The
library exports exactly the 15 functions the header declares, in every build configuration
(`tests/check_exports.py`).

## What the caller must guarantee

The library can't tell a valid pointer from a dangling one. Breaking any of these rules is undefined behavior, not an
error status:

- Every input `(pointer, length)` with a non-zero length points to `length` bytes that stay readable and unchanged
  for the whole call.
- Every output slot (`ardia_buf *` or `ardia_sync_keys **`) is aligned, writable, not touched by anything else
  during the call, and empty: `{NULL, 0}` for a buffer, `NULL` for a key.
- A buffer the library filled keeps its `ptr` and `len` unchanged until it goes back to `ardia_buf_free`, and goes back
  exactly once.
- A key handle comes from `ardia_sync_keys_new` and isn't used after `ardia_sync_keys_free`. Nothing else may use it
  while it is being freed.

## What the library checks

Only nulls, lengths and contents. Nothing more:

- A `NULL` input pointer with length 0 is an empty input. A `NULL` input pointer with a non-zero length, a `NULL` key
  or a `NULL` output slot returns `ARDIA_STATUS_INVALID_ARGUMENT`.
- A length over its cap (`ARDIA_MAX_*`) returns `ARDIA_STATUS_TOO_LARGE` before the pointer is read. Entropy must be
  exactly `ARDIA_ENTROPY_BYTES`.
- Text inputs that aren't UTF-8 return `ARDIA_STATUS_INVALID_ARGUMENT`.
- An output slot that isn't empty returns `ARDIA_STATUS_OUTPUT_IN_USE`, and the slot is left as it was.

## Results

- Every call returns an `ardia_status`. `ARDIA_STATUS_OK` is the only success.
- On `ARDIA_STATUS_OK` the buffer holds the result. A result can be empty, and then the buffer stays `{NULL, 0}`. With any
  other status, except `ARDIA_STATUS_OUTPUT_IN_USE` or a `NULL` slot, it holds a JSON error: `{"code": "..."}`, plus
  `count` for `wordCount` and `index` (0-based word position) for `unknownWord`. Error JSON never contains phrase
  words, passwords or payloads; show the user's own input highlighted at `index` instead.
- Secret results (opened payloads, passwords, entropy, phrases) are plain bytes, never JSON. Copy out what you need,
  then free the buffer.
- `ardia_buf_free(&buf)` zeroes the bytes, frees them and resets the slot to `{NULL, 0}`. Freeing a reset slot or
  passing `NULL` does nothing. Freeing another copy of a buffer that was already freed is a double free.
- `ardia_sync_keys_new` writes a new handle that owns the derived keys and zeroes them when freed. A handle never
  changes after it's made, so threads may share it, but its free must be synchronized with every user.

## Runtime

The library keeps no globals and starts no threads. It reads no files. The only system call it makes is asking the
OS for random bytes, in `ardia_sync_seal`, `ardia_sync_new_file_id` and `ardia_phrase_generate_entropy`. A panic aborts
the process in release builds.

## Nonces

Files and local state are sealed only with OS-random nonces. Passwords are sealed with their HMAC-derived deterministic
nonce. No C function takes a caller-chosen nonce. The fixed-nonce sealing that reproduces the committed vectors is
the Rust function `SyncKeys::seal_with_nonce`. It exists only under `cfg(test)` or the `fixtures` feature, which only
the test crate `ardia-sync-vectors` turns on.

## Reading what other platforms wrote

Password reads follow Swift exactly, because Swift wrote most existing vaults. Base64 decodes like Foundation's
`Data(base64Encoded:)`: extra trailing `=` are accepted, and whitespace and missing padding are not. One leading U+FEFF
is dropped from an opened password. Writes stay canonical. `tests/password-read-cases.json` and
`tests/phrase-cases.json` record where Linux, Windows and Kotlin read differently today.

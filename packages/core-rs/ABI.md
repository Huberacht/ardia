# ardia_core C ABI

`include/ardia_core.h` is generated by cbindgen (`ARDIA_WRITE_HEADER=1 cargo test -p ardia-ffi --test header`) and
carries no comments, so its rules live here. C++ can include it directly: it has its own `extern "C"` guard.

## Calls

- Every call returns an `ardia_status`. `ARDIA_STATUS_OK` is the only success.
- Inputs are `(pointer, length)` pairs. A length of 0 may come with any pointer, `NULL` included. A non-zero length needs a
  readable pointer, or the call returns `ARDIA_STATUS_INVALID_ARGUMENT`. Text inputs must be UTF-8.
- Every input has a cap (`ARDIA_MAX_*`). A longer one returns `ARDIA_STATUS_TOO_LARGE` before the pointer is read.
  Entropy is exactly `ARDIA_ENTROPY_BYTES`.
- The library keeps no globals and starts no threads. It reads no files and makes no system calls except asking the OS for
  random bytes (`ardia_sync_seal`, `ardia_sync_new_file_id`, `ardia_phrase_generate_entropy`). A panic aborts the
  process in release builds.

## Output buffers

- A call that returns bytes writes them into an `ardia_buf` the caller owns. Pass it as `{NULL, 0}`. A slot that already
  holds anything (`ptr` not `NULL` or `len` not 0) is refused with `ARDIA_STATUS_OUTPUT_IN_USE` and left untouched,
  so a held buffer is never lost or overwritten.
- On `ARDIA_STATUS_OK` the buffer holds the result. A result can be empty, and then the buffer stays `{NULL, 0}`. With any
  other status, except `ARDIA_STATUS_OUTPUT_IN_USE` or a `NULL` slot, it holds a JSON error: `{"code": "..."}`, plus `count` for `wordCount` and
  `index` (0-based word position) for `unknownWord`. Error JSON never contains phrase words, passwords or payloads;
  show the user's own input highlighted at `index` instead.
- Each filled buffer has exactly one owner. Release it once with `ardia_buf_free(&buf)`, which zeroes the bytes,
  frees them and resets the slot to `{NULL, 0}`. Freeing a reset slot or passing `NULL` does nothing. Freeing a copy of
  the struct after the original was freed is a double free; keep one copy.
- Results that are secrets (opened payloads, passwords, entropy, phrases) are plain bytes, never JSON. Copy out what
  you need before freeing.

## Keys

- `ardia_sync_keys_new` writes a new handle into `*out`, which must be `NULL` (otherwise
  `ARDIA_STATUS_OUTPUT_IN_USE`). The handle owns the derived keys and zeroes them when freed.
- A handle never changes after it's made, so any number of threads may use one at once. `ardia_sync_keys_free` must not
  run while any other call is using that handle. Synchronize the free with every user, then never touch the handle
  again. Freeing `NULL` does nothing.

## Nonces

The shipped library seals files and local state only with OS-random nonces, and passwords with their HMAC-derived
deterministic nonce. `ardia_sync_seal_with_nonce` exists only with the `fixtures` cargo feature, which tests turn on to
reproduce the committed vectors. It is never in the header, and a release build never exports it.

## Reading what other platforms wrote

Password reads follow Swift exactly, because Swift wrote most existing vaults. Base64 decodes like Foundation's
`Data(base64Encoded:)`: extra trailing `=` are accepted, and whitespace and missing padding are not. One leading U+FEFF
is dropped from an opened password. Writes stay canonical. `tests/password-read-cases.json` and
`tests/phrase-cases.json` record where Linux, Windows and Kotlin read differently today.
